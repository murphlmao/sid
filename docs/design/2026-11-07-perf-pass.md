# Perf pass, 2026-11-07

## Method

* Release build (`cargo build --release -p sid`, base `ce23a79`), 1920x1080 headless
  sway, `scripts/perfcap.sh` (fixed 8 s windows, `perf stat --no-scale`,
  instructions:u). The box was shared and busy, so **no wall-clock numbers**: only
  instruction counts and frame counts. Arms are interleaved, same build mode.
* Per-frame cost = (I_driven - I_idle) / (F_driven - F_idle). Network is driven by
  pointer hover over the Ports table (one frame per row crossing); the others by wheel.
* `perfcap.sh` pointed at a `vptr2.py` that never existed in the tree; it now uses
  `scripts/cap-input/vptr.py` (which has `scroll`/`hover`). New `--unfocus` flag parks a
  second client on top so sid loses keyboard focus.
* Wakeups/sec were not captured: `perf stat -e context-switches` reports `:u` and counts
  0 for user-only. Frame counts and instructions are the proxy.

## Baseline (before)

| tab | idle, 8 s | render cost / frame |
|---|---|---|
| Settings | 0 frames, ~0 instr | 5.8 M |
| SSH (no session) | 0 frames, ~0 instr | 8.3 M |
| Database | 0 frames, ~0 instr | n/a (no table in empty state) |
| Workspaces | 0 frames, ~0 instr | n/a |
| Network (Ports table, hover) | 0 frames, ~0 instr | 26.4 M |
| System (focused) | 4 frames, 335 M | 31.8 M |
| System (unfocused, 20 s) | **10 frames, 871 / 961 M** | - |

Startup, settings tab: ~543 M instructions:u from exec to steady state (4 frames);
RSS 134 MB. Typing in a filter was not separately measured.

Every tab but System sits at zero frames and zero instructions when idle. System's 2 s
sysinfo probe is the only idle cost (84 M a tick here; the earlier doc measured
0.6-2.5 G on a busier process table).

## Changes

1. `perf(system)`: while no sid window has keyboard focus, the System tick probes every
   5th tick (10 s) instead of every 2 s; focus return probes immediately.
   Unfocused 20 s window: **871 / 961 M -> 177 / 192 M instr (-80 %), 10 -> 2 frames.**
2. `perf(ssh)`: the shell read loop (33 ms poll, one tokio hop per tick per session)
   polls at 133 ms while no sid window is focused. Unmeasured (needs a live session /
   the ssh fixture); it is a single interval choice, full rate returns on focus.
3. Tooling: perfcap fix + `--unfocus`.

## After

| scenario | before | after |
|---|---|---|
| System, unfocused, 20 s | ~916 M instr, 10 frames | ~185 M, 2 frames |
| everything else | unchanged | unchanged (no render code touched) |

No rendering code changed, so no A/B captures were needed.

## What's left

* **Table cells are still the frame** (Network: 26.4 M/frame; ~121 K instr/cell per
  `2026-07-27-table-frame-cost.md`). The table is still gpui-component's, so the earlier
  pricing (measure passes 4.6 %, per-cell wrapper div ~11 %) still applies; the cell
  counts were not re-measured. The per-cell `data_cell` div carries mono font, clamp
  and padding, so removing it means moving style to `render_tr`/column paddings, in
  files other agents are editing tonight. Not attempted.
* The focused System probe (84 M+ per tick) could use a narrower `ProcessRefreshKind`.
* Typing-in-filter and live-SSH-session frame costs, and true wakeup counts
  (`perf stat -e sched:sched_switch` or `strace -c -f`), still need a pass.

## Table cells without a wrapper node (2026-11-08, `night/perf-tables`)

Renderer: gpui-pre 0.3.11 / gpui-component 0.9 `DataTable`. Same method as above
(instructions:u, `perf stat --no-scale`, release, 1920x1080, arms interleaved, binaries
copied to `target/ab/sid-{base,new}`; `scripts/ab.sh` for Network hover, `perfcap.sh` scroll
for System).

**Re-measurement.** Network Ports, 1920x1080: **236 cell builds per frame**
(`GPUI_MEASUREMENTS=1`; identical before/after). Of these ~28 (12 %) are gpui's
`measure_item` passes whose result is discarded, as in the 07-27 analysis; they are still
unreachable from sid and priced there at 4.6 % of a frame, so they stay. Baseline:
Ports 30.3 M instr/frame, Processes (System) 37.5-41 M.

**Change.** Every text cell in Ports, Connections and Processes was
`div().px_2().text_mono().text_color().child(text)`, one extra taffy node + `Div` machinery
per cell. Now `sid_ui::table::CellText` is a bare element that pushes the same
`TextStyleRefinement` (mono, ink, and for ellipsis cells `whitespace_normal` + line clamp +
`…`) around a `SharedString` text node via `Window::with_text_style`, so the cell costs the
text node only. The `px_2` inset moved to `Column::paddings` via
`FillColumns::inset_cells(cols)` (default cell padding + 0.5rem, zoom-aware). Because the
header shares `Column::paddings` and parks its chevron against the right edge, only the
**left** padding grows, and `sortable_th` cancels it with a negative left margin so header
text and chevrons do not move.

| scenario | before | after | delta |
|---|---|---|---|
| Network Ports, hover, per frame (4 rounds each) | 30.3 M (30.3/30.3/30.3/30.3) | 27.7 M (27.8/27.7/27.7/27.7) | **-8.6 %** |
| System Processes, wheel, per frame (3 rounds) | 37.5 / 37.5 / 41.0 M | 35.4 / 35.4 / 35.2 M | **-5.6 % (vs the stable pair)** |

Captures: Network Ports and System Processes, cosmos and cosmos-light, 1920x1080 and
1280x800, before/after. Network is **pixel-identical except the live Memory cell**
(pixel-diffed: 257 differing pixels, all inside that one cell, in all four captures);
System differs only by live data (rows/CPU/uptime), column x-positions and header match.
Known, deliberate difference: an ellipsised cell now ends 8px closer to its column's right
edge (default 8px right padding instead of 16px), because growing the right padding would
move every header chevron. The DB results grid was not captured: `ResultDelegate` was not
touched (its cells carry their own layout) and needs a live connection.

**Not done / next.** Services, Docker, Kube pods and the Fleet table still use the old
`data_cell` div (mixed badge/prose columns; same recipe applies: `inset_cells` plus
`CellText`). The remaining per-cell cost is gpui-component's own: each cell gets
`.id(format!("table-cell:{r}:{c}"))` (a `String` alloc plus an element id per cell,
`state.rs` render_table_row) and `render_col_wrap` + `render_cell` are two nodes per cell;
neither is reachable without vendoring the table. `ProcessRefreshKind` narrowing in
sid-sysinfo was skipped: another agent owns `crates/sid-sysinfo/**` (sysinfo 0.40 upgrade),
note for later.
