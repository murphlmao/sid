# Perf pass, 2026-11-07

## Method

* Release build (`cargo build --release -p sid`, base `ce23a79`), 1920x1080 headless
  sway, `scripts/perfcap.sh` (fixed 8 s windows, `perf stat --no-scale`,
  instructions:u). The box was shared and busy, so **no wall-clock numbers**: only
  instruction counts and frame counts. Arms are interleaved, same build mode.
* Per-frame cost = (I_driven - I_idle) / (F_driven - F_idle). Network is driven by
  pointer hover over the Ports table (one frame per row crossing); the others by wheel.
* `perfcap.sh` pointed at a `vptr2.py` that never existed in the tree; it now uses
  `scripts/cap-input/vptr.py` (which has `scroll`/`hover`). New `--unfocus` flag parks a
  second client on top so sid loses keyboard focus.
* Wakeups/sec were not captured: `perf stat -e context-switches` reports `:u` and counts
  0 for user-only. Frame counts and instructions are the proxy.

## Baseline (before)

| tab | idle, 8 s | render cost / frame |
|---|---|---|
| Settings | 0 frames, ~0 instr | 5.8 M |
| SSH (no session) | 0 frames, ~0 instr | 8.3 M |
| Database | 0 frames, ~0 instr | n/a (no table in empty state) |
| Workspaces | 0 frames, ~0 instr | n/a |
| Network (Ports table, hover) | 0 frames, ~0 instr | 26.4 M |
| System (focused) | 4 frames, 335 M | 31.8 M |
| System (unfocused, 20 s) | **10 frames, 871 / 961 M** | - |

Startup, settings tab: ~543 M instructions:u from exec to steady state (4 frames);
RSS 134 MB. Typing in a filter was not separately measured.

Every tab but System sits at zero frames and zero instructions when idle. System's 2 s
sysinfo probe is the only idle cost (84 M a tick here; the earlier doc measured
0.6-2.5 G on a busier process table).

## Changes

1. `perf(system)`: while no sid window has keyboard focus, the System tick probes every
   5th tick (10 s) instead of every 2 s; focus return probes immediately.
   Unfocused 20 s window: **871 / 961 M -> 177 / 192 M instr (-80 %), 10 -> 2 frames.**
2. `perf(ssh)`: the shell read loop (33 ms poll, one tokio hop per tick per session)
   polls at 133 ms while no sid window is focused. Unmeasured (needs a live session /
   the ssh fixture); it is a single interval choice, full rate returns on focus.
3. Tooling: perfcap fix + `--unfocus`.

## After

| scenario | before | after |
|---|---|---|
| System, unfocused, 20 s | ~916 M instr, 10 frames | ~185 M, 2 frames |
| everything else | unchanged | unchanged (no render code touched) |

No rendering code changed, so no A/B captures were needed.

## What's left

* **Table cells are still the frame** (Network: 26.4 M/frame; ~121 K instr/cell per
  `2026-07-27-table-frame-cost.md`). The table is still gpui-component's, so the earlier
  pricing (measure passes 4.6 %, per-cell wrapper div ~11 %) still applies; the cell
  counts were not re-measured. The per-cell `data_cell` div carries mono font, clamp
  and padding, so removing it means moving style to `render_tr`/column paddings, in
  files other agents are editing tonight. Not attempted.
* The focused System probe (84 M+ per tick) could use a narrower `ProcessRefreshKind`.
* Typing-in-filter and live-SSH-session frame costs, and true wakeup counts
  (`perf stat -e sched:sched_switch` or `strace -c -f`), still need a pass.
